# gpsfree

GPS-free localisation benchmark. Algorithms get IMU, magnetometer, barometer and echo ranges plus a prior 3D map,
and must estimate their position without ever seeing ground truth. Currently scored on **drones over Yosemite**.

## Scoring rules

- **Error** is the 3D Euclidean distance between the estimate and the true position, sampled at 10 Hz.
- **Distance travelled** is the 3D arc length of the true path, so climbs and descents count.
- **Score** (the one ranked number): the mean of log₁₀(error) over every sample from 100 m travelled to the end of
  the route, with error floored at 1 m. That is the geometric-mean error along the whole flight: an order of
  magnitude, not tied to any checkpoint and with no assumption about how error grows. Median over routes × seeds.
  Shown in metres and as log₁₀; lower is better. A non-finite estimate scores ∞.
- **Diagnostics** (shown, not ranked):
  - *MAE per band*: mean error over 0–250, 250–500, 500–1000, 1000–2000 and 2000+ m travelled.
  - *Lost at*: distance travelled when error first exceeds 50 m (route length if never).
  - *Growth k*: slope of log error vs log distance — ≈3 raw IMU drift, ≈1 linear drift, ≈0 bounded.
  - `xy_rmse_m` / `z_rmse_m` in `results.json`.
- The rules live in `benchmark/suite.json`, `benchmark/hardware/` and `gpsfree/evaluate.py`. Changing any of them
  (or any route) changes the suite fingerprint and marks every existing result ⚠ stale until it is re-run.

## Rules for experiments

- **Every number comes from the CI scorer.** An experiment is `experiments/<name>/algo.py` defining
  `Navigator(gpsfree.Algorithm)`, scored with `uv run gpsfree eval <name>`: the exact code CI re-runs. Don't report
  numbers from side scripts with their own metric, noise model or initial conditions. If an idea can't be expressed
  as a `Navigator`, change the harness in a PR so everyone gets it.
- **No ground truth.** A `Navigator` sees only the start pose, sensor callbacks and the prior map.
- **Real hardware.** Set `hardware = "<profile>"` on the `Navigator` to replace the suite's IMU and magnetometer
  with a real part from `benchmark/hardware/<profile>.json`. Leave it unset (`None`) to use the suite's default
  sensors. Profiles store datasheet numbers in datasheet units, with the document revision, table and URL. Any
  number that isn't from a datasheet is marked `ASSUMPTION`. `gpsfree/sensors.py:hardware_sensors` converts them:
  - white noise σ = noise density × √rate;
  - a constant per-run bias drawn from N(0, in-run bias stability);
  - for parts that publish no bias stability, the bias σ is the temperature coefficient × `delta_temp_c`.
- **Hardware under $3,000.** The method's hardware cost (cost column below) must be under $3,000; CI fails the PR
  otherwise and the leaderboard leaves it out. Methods on the suite's default sensors have no price and are allowed.
- **Variants reuse code.** Subclass another experiment with `load_algorithm("imu_deadreckoning")` rather than
  copying it. CI only re-verifies experiments a PR touches, so if you change a base, re-run and commit its
  subclasses' `results.json` too.

## Submitting

```sh
uv run gpsfree fetch yosemite         # download + bake the world into data/worlds
uv run gpsfree new my_method          # copy a template into experiments/my_method
uv run gpsfree eval my_method         # run the suite, writes experiments/my_method/results.json
```

1. Commit `experiments/<name>/algo.py` and `results.json`, open a PR.
2. CI re-runs only the experiments the PR touches and fails if the committed `results.json` doesn't reproduce or
   the hardware costs $3,000 or more. Scoring worse never blocks a merge.
3. After merge, CI regenerates the leaderboard above (top 5 methods) and commits it to `main`. Don't edit it by hand.
